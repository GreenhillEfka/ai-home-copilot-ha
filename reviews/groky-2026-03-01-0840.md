### Potenzielle Issues Identifiziert

#### ⚠️ Issue 1: Duplicate Blueprint Registration Risk

**Problem:** In `app.py` werden die Phase 5 Blueprints direkt bei `create_app()` registriert. Wenn Tests zusätzlich `register_blueprints()` aus `core_setup.py` aufrufen, könnte es zu Duplikaten kommen.

**Code-Stelle in `app.py` (Zeilen ~135-165):**
```python
# Phase 5 APIs: Notifications, Sharing, Collective Intelligence
try:
    from copilot_core.notifications.api import notifications_bp, init_notifications_api
    # ... init code ...
    if "notifications" not in app.blueprints:
        app.register_blueprint(notifications_bp, url_prefix='/api/v1')
except Exception:
    logging.getLogger(__name__).exception("Failed to register Notifications API blueprint")
```

**Code-Stelle in `core_setup.py` (register_blueprints Funktion):**
```python
# Register Phase 5 APIs (v7.11.0) — Notifications, Sharing, Collective Intelligence
try:
    from copilot_core.notifications.api import notifications_bp, init_notifications_api
    # ... init code ...
    # app.register_blueprint(notifications_bp)  # consolidated to app.py (single source)
except Exception:
    _LOGGER.exception("Failed to register Notifications API v7.11.0")
```

**Beobachtung:** Die Registration in `core_setup.py` ist auskommentiert mit dem Kommentar `# consolidated to app.py (single source)`. Das ist korrekt.

#### ⚠️ Issue 2: Inkonsistente URL-Prefix Behandlung

**Problem:** Die drei Phase 5 Blueprints verwenden unterschiedliche Ansätze für URL-Prefixes:

| Blueprint | Registration | URL-Prefix | Route-Definition |
|-----------|-------------|------------|------------------|
| `notifications` | `url_prefix='/api/v1'` | `/api/v1` | `/notifications` → `/api/v1/notifications` |
| `sharing` | kein Prefix | (none) | `/api/v1/sharing/entities` (hartkodiert) |
| `federated` | kein Prefix | (none) | `/api/v1/federated` (hartkodiert) |

**Empfehlung:** Konsistente Behandlung für alle Phase 5 Blueprints:

```python
# Empfohlene konsistente Registration (alle mit url_prefix)
if "notifications" not in app.blueprints:
    app.register_blueprint(notifications_bp, url_prefix='/api/v1')

if "sharing" not in app.blueprints:
    app.register_blueprint(sharing_bp, url_prefix='/api/v1')

if "federated" not in app.blueprints:
    app.register_blueprint(federated_bp, url_prefix='/api/v1')
```

**Und in den API-Dateien die Routes ohne `/api/v1` Prefix definieren:**
```python
# sharing.py - statt:
@sharing_bp.route('/api/v1/sharing/entities', methods=['GET'])
# sollte sein:
@sharing_bp.route('/sharing/entities', methods=['GET'])
```
