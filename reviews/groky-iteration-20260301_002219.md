**Additional Failure:**
- `test_event_store.py::TestEventStoreNormalization::test_n3_spec_format_normalized` - N3 format issue

### Root Cause Analysis

The Phase 5 blueprint registration failures stem from a **blueprint name collision** in the test environment:

```
ValueError: The name 'openai_compat' is already registered for this blueprint.
```

This occurs in `core_setup.py` line 904 when `register_blueprints()` is called during test fixture setup. The `create_app()` function already registers `openai_compat_bp`, and then `register_blueprints()` tries to register it again.

```python

# collective_intelligence/api.py - NO type hints
def get_status():  # Missing -> Response
def start_service():  # Missing -> Response
def submit_update():  # Missing -> Response
```

### Type Hint Recommendations

Phase 5/6 APIs should include:
1. Return type annotations (`-> Response`, `-> tuple[Response, int]`)
2. Parameter type hints for route parameters
3. Type hints for module-level variables

**Example Fix:**
```python
from flask import Response

@notifications_bp.route("/notifications", methods=["GET"])
@require_api_key
def get_notifications() -> tuple[dict, int]:
    """Get notification history."""
    ...
```
